# Уведомления о бронях в Telegram

У каждого tenant-а есть обычный код в `Telegram.ConnectionCode`. Вы сами задаёте
его в `appsettings.json` и передаёте владельцу бизнеса. Хеширование, генератор
и одноразовые коды не нужны.

## Настройка кодов организаций

В существующей записи организации укажите:

```json
{
  "Id": "thetochka",
  "Telegram": {
    "ConnectionCode": "TOCHKA-MY-CODE"
  }
}
```

Это фрагмент одной записи `Organizations.Items`, остальные настройки организации
сохраняются. Для автомойки задайте другой код в её записи. В основном
`table-reservations/appsettings.json` уже добавлены разные коды обоим tenant-ам;
их можно заменить своими.

Коды должны отличаться между организациями, не содержать пробелов и занимать
не более 128 символов. Регистр учитывается. Пустое значение отключает новые
подключения по коду для этой организации. Код не входит в публичный ответ
`/api/tenant/public-config` и не выводится в журналы приложения.

После изменения настроек перезапустите сервер. Учитывайте, что настройки
окружения и `appsettings.Development.json` / `appsettings.Production.json`
могут переопределять основной файл. Альтернатива для конфигурации окружения:
`Organizations__Items__0__Telegram__ConnectionCode` (проверьте организацию по индексу).

## Подключение клиентом

1. Передайте владельцу код его бизнеса и имя бота `@reservremindbot`.
2. Владелец создаёт группу или выбирает существующую, добавляет бота
   и назначает его администратором.
3. От своего аккаунта владельца/администратора группы он отправляет:

   ```text
   /connect TOCHKA-MY-CODE
   ```

   Можно явно адресовать команду боту:

   ```text
   /connect@reservremindbot TOCHKA-MY-CODE
   ```

4. Бот проверяет права отправителя, находит tenant по коду и сохраняет группу
   в Turso. После ответа «Уведомления … подключены» группа получает копии
   сообщений о бронях выбранного бизнеса.

Нельзя отправлять команды анонимно от имени группы: нужен личный аккаунт её
владельца/администратора. Передавайте код только сотрудникам соответствующего бизнеса.

Код многоразовый. Повторная команда в той же группе допустима. Команда с этим
кодом в другой группе переносит уведомления туда: у бизнеса одна подключённая
группа. Одна группа также может быть подключена только к одному бизнесу.

Для отключения отправьте `/disconnect` или `/disconnect@reservremindbot`.
Для повторного подключения используйте тот же код. Изменение кода в настройках
не отключает уже подключённую группу; оно меняет код для следующих команд `/connect`.

## Однократная настройка бота на сервере

Бот уже создан; укажите его параметры в корневом разделе `Telegram`:

```json
"Telegram": {
  "BotToken": "ТОКЕН_ВАШЕГО_БОТА",
  "BotUsername": "reservremindbot",
  "WebhookSecret": "СЛУЧАЙНАЯ_СТРОКА_ДЛЯ_WEBHOOK"
}
```

Токен задавайте через секреты окружения `Telegram__BotToken` или игнорируемый файл
настроек. `BotUsername` указывается без `@`. `WebhookSecret` — отдельный секрет
для связи Telegram с сервером: 32–256 символов из A–Z, a–z, 0–9, `_` и `-`.
Клиент его не вводит. При пустом токене интеграция отключена.

Перед первым запуском примените добавочную миграцию к нужной базе:

```powershell
dotnet run --project table-reservations --no-launch-profile -- --migrate
```

Создаются `telegram_groups` и `notification_deliveries`; повторная миграция
допустима. При обычном старте сервер проверяет схему, не создавая таблицы.
Таблица `telegram_used_codes` от предыдущей реализации, если она уже создана,
не используется и не мешает повторному подключению.

Затем запустите сервер и зарегистрируйте webhook на публичном HTTPS-адресе backend.
Пример PowerShell, если секреты уже заданы через переменные окружения:

```powershell
$webhookBody = @{
    url = 'https://YOUR_BACKEND/integrations/telegram/webhook'
    secret_token = $env:Telegram__WebhookSecret
    allowed_updates = @('message')
    max_connections = 1
} | ConvertTo-Json
$telegramEndpoint = 'https://api.telegram.org/bot' + $env:Telegram__BotToken + '/setWebhook'
Invoke-RestMethod -Method Post -Uri $telegramEndpoint -ContentType 'application/json' -Body $webhookBody
```

Telegram обращается к `/integrations/telegram/webhook` без заголовка tenant-а.
Подлинность запроса проверяется по `X-Telegram-Bot-Api-Secret-Token`.
Бот должен быть администратором для надёжной проверки прав отправителя:
[setWebhook](https://core.telegram.org/bots/api#setwebhook),
[getChatMember](https://core.telegram.org/bots/api#getchatmember).

## Доставка

- В группу копируются оба сообщения о новой брони: подтверждение клиенту
  и уведомление администратору. WhatsApp продолжает работать независимо от Telegram.
- Также копируются включённые напоминания за час. Сейчас существующий worker
  поддерживает их только для ресторана при `ReservationReminders:Enabled=true`.
- Успех напоминаний сохраняется отдельно по организации, брони и каналу. При
  частичном сбое повторяется неуспешный канал в оставшемся часовом окне.
- Ответ создания брони содержит `telegramSent`: `true`, если обе копии приняты
  Telegram. Ошибка доставки не отменяет сохранённую бронь.
- Преобразование группы в супергруппу обновляет идентификатор через сервисное
  сообщение Telegram.
- Автоматического повтора уведомлений о новых бронях пока нет. Для напоминаний
  используйте один активный worker; авария между отправкой сообщения и сохранением
  результата в БД может привести к повтору.
- Для Telegram HTTP-клиента отключено стандартное логирование URL с токеном.

Проверка без внешних отправок:

```powershell
dotnet test table-reservations.slnx
```

После настройки сервера подключите тестовую группу и создайте тестовую бронь
через сайт нужной организации. Проверьте две копии в группе, прежнюю доставку
WhatsApp и отключение через `/disconnect`.
